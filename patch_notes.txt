SECURITY FIX — C1 Critical: Open registration endpoint (owner takeover)
------------------------------------------------------------------------
File patched on server: /opt/journal-dashboard/src/api/onboarding_routes.py

Problem:
  POST /api/register had no guard against anonymous account creation.
  The first registered account is granted the 'owner' role. If the owner
  account was ever deleted or on a fresh deploy, any anonymous user who
  hit the endpoint first would gain full admin access to the journal.

Fix applied:
  Added an owner-exists check at the top of the DB block. If any user
  with role='owner' already exists, the endpoint immediately returns
  HTTP 403 "Registration is closed" before processing any input.

  Before:
    conn = get_db()
    try:
        existing = conn.execute(
            "SELECT id FROM users WHERE username = ? OR email = ?", ...
        ...
        count = conn.execute("SELECT COUNT(*) as c FROM users")...
        role = "owner" if count == 0 else "viewer"

  After:
    conn = get_db()
    try:
        owner_exists = conn.execute(
            "SELECT 1 FROM users WHERE role = 'owner' LIMIT 1"
        ).fetchone()
        if owner_exists:
            raise HTTPException(403, "Registration is closed")
        ... (rest unchanged)

Verified:
  curl POST /api/register with valid body → 403 (was 422 before patch)
  Service restarted cleanly: systemctl is-active journal-dashboard → active

Context:
  Discovered by 4-agent security audit run on 2026-05-02 (see
  security_audit_report.txt for full findings — 1 critical, 10 high,
  11 medium, 7 low). This was the only change deployed from that audit.
